# 見た目が変わるため今回は入れないもの（記録）

ユーザー合意（2026-11-23）「現状のデザインの初期状態を守る」により、デザイン資料に「本実装で直す」「残っている課題」として挙がっていても、**見た目が変わるもの**は今回の実装に入れず、ここに記録する。入れるときはデザイン側の更新（Claude Design）と再現度テストの基準画像の作り直しを伴う。

| 出典 | 内容 | 見た目への影響 | 状態 |
| --- | --- | --- | --- |
| 実装ガイド 9章「部品の直し」・部品シートで見つかった不足 | 小さなチップ（`.chip.sm`）の縁を `--line` にして 3:1 以上にする | 縁が濃くなる | 保留 |
| 実装ガイド 9章 | 選択の並びを選択メニューにする基準を、数だけでなくシートの幅でも判断（全体設定の「検索先」など） | 並びがメニューに変わる | 保留 |
| レビュー 2章「残っている課題」 | 主役と脇役の差（脇役のガラスを沈める） | ガラスの強さが変わる | 保留 |
| レビュー 2章 | 帯のアイコンが多い（優先度の低いボタンを最初から「…」へ） | 帯の並びが変わる | 保留 |
| レビュー 2章 | アクセントの青の使い道（進み具合は文字色、バッジは赤系か文字色） | 色が変わる | 保留 |
| レビュー 2章 | スマホの受け取りの帯が時計の数字に重なる | 帯の位置が変わる | 保留 |
| レビュー 2章 | その他メニューに「使い方」を足す | メニューの項目が増える | 保留 |
| 実装ガイド 9章 | 重なりの順を数字の直書きから層のトークンにする | 変わらない（P3 で実施） | P3 |
| 実装ガイド 9章 | 行の中に直接書いた見た目（style 属性、約440か所）をクラスとトークンに | 変わらない（再現度テストで確認しながら P3） | P3 |

見た目が変わらない標準化（`<dialog>`＋`showModal()`、popover と anchor positioning、inert、Navigation API との連動）は、再現度テストが落ちないことを確かめて P3 で入れる。

## 仕様書に従って、プロトタイプと変えたもの

プロトタイプは確認用の都合で仕様書と違う値を持っている所がある。仕様書が「本実装では」と明記しているものは仕様書に従う（見た目の差はその設定を開いた画面だけに出る）。

| 箇所 | プロトタイプ | 本実装 | 根拠 |
| --- | --- | --- | --- |
| 検索「新しいタブで開く」の既定 | オン | オフ | 仕様書 3章「登録済みウィジェット」（本実装の既定はオフ）、実装ガイド 付録（プロトタイプでは確認中に画面が移らないよう既定をオンにしている） |
| ボードを削除したときの名前 | 振り直さない | 「ボード 1」から振り直す | 仕様書 2章「ボードの名前は…追加や削除のたびに振り直し」 |
