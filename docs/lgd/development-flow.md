### 見た目の正本としての CSS

`src/app/styles/dashboard.css` はプロトタイプの `<style>` をそのまま移したもの。値を手で変えない。プロトタイプ側が変わったら丸ごと取り込み直す。クラス名（`.w` `.in` `.chip` `.nb` `.sheet` …）と DOM の形はプロトタイプと同じにする。こうすると再現度テストの差が小さくなり、部品シートとも対応がとれる。Vue のテンプレートは空白も描画に効くため、改行を足す整形系の lint ルールは切ってある（`eslint.config.mjs`）。

行の中に直書きされた `style="…"`（約440か所）は、まず**そのまま移す**。トークンとクラスへの置き換え（実装ガイド 9章）は、見た目が変わらないことを再現度テストで確かめながら P3 で行う。

ユーザー合意（2026-11-23）で、次の4層に分けて進める。層ごとに `.claude/agents/` にエージェント定義、`.claude/skills/` に手順を置く。

| **判定層** | 合格ラインの判定、差分の原因の切り分け（どの部品・どの値か）、改善の指示書づくり。数値だけで合否を決め、主観で合格にしない | `vrt/report/`（生成物）、`docs/lgd/vrt-results.md` | `lgd-vrt-judge` |
| **テスト実施層** | 再現度テストのハーネスとシナリオ、基準画像の生成、Vitest の単体テスト、Playwright の e2e、Storybook の操作テスト | `vrt/**`、`e2e/**`、`*.test.ts`、`docs/lgd/vrt.md` | `lgd-vrt-runner` / スキル `lgd-vrt` |
| **ウィジェット実装層** | 各ウィジェットの中身、記録（data）の定義と検証、計算（必要なら `src/tools` の Operation） | `src/widgets/<id>/**`、`src/widgets/index.ts`、`src/tools/**` | `lgd-widget` / スキル `lgd-add-widget` |

## 4. 作り方の決まり

### ストアと状態

- `Dashboard`（`src/app/store/store.ts`）が唯一の状態。土台の部品は `useDash()` で受け取る。
- **種類 ID と配置 ID を分ける**（[review-flow #5](./review-flow.md)、この PR で対応中）。種類 ID は登録のキー（`links`）で、登録（`src/app/registry/registry.ts`）と `WIDGETS`・`WIDGET_DATA` はこれで引く。配置 ID は置いた1個の ID で、最初の1個は種類 ID そのもの（`links`。既存7個の ID と見た目は変えない）、2個目以降は `<kind>#<n>`（`links#2`）。`order`・`place`・`sizes`・`off`・`pins`・`lockSz`・`pgW` と区画 `w:<配置ID>` は配置 ID で持つ。`multi: false` の種類は2個目を作れない。全画面は「`pg` の種類で `pgW[配置ID]` が真の配置」を汎用に扱い、種類ごとの分岐（時計・スケッチ専用の一覧など）を足さない。複数置く UI と記録の共有の選択は P3、共有の対象（`share`）は未決定（実装ガイド 7.6）で、既定は独立。
- 状態は3つに分ける: `g`（区画「全体」に保存）、`cfg[配置ID]` と `data[配置ID]`（区画 `w:<配置ID>` に保存）、`ui`（保存しない一時状態）。これとは別に、**実行状態**（動いているか・終わる時刻・経過の基準など）は Dashboard の実行管理 `runtimeOf(d)`（`src/app/runtime/runtime.ts`）に配置 ID ごとに持ち、保存しない（下の「実行の寿命」）。プロトタイプの `state` のキーはこのどれかへ移す。保存しないもの（実装ガイド 6章: 開いているシート・今の画面・前面表示・再生中かどうか・録音、画像変換の一覧と画像、現在地、スクリプトの実行結果、会話保存オフの会話、生成途中の応答）と鍵・認証情報は `cfg`/`data` に入れない。
- ウィジェットの記録は `WidgetDataDef`（`version`・`initial`・`sanitize`・必要なら `toSaved`・`migrate`）で定義し、`src/widgets/index.ts` の `WIDGET_DATA` に登録する。読み込み時は必ず `sanitize` を通し、知らない項目は捨て、足りない項目は既定値で補う。登録の `store` はここから引き、二重に書かない（review #6）。
- **区画の版**（[review-flow #1](./review-flow.md)、この PR で対応中）: 全体の区画に `v`、ウィジェットの区画に `v`（区画の形の版）と `dv`（記録の版＝`WidgetDataDef.version`）。未来の版・不正な区画は読み込まず、保存 bytes にも書かない（読み取り専用として残す）。古い版は `migrate` があれば移し、無ければ未来の版と同じく残す。記録の形を変えたら `version` を上げて `migrate` を足す。
- **変わった区画だけ書く**（review #2）。同じ区画を2つのタブで同時に変えたときは後勝ちで、タブ同期（storage イベント・Web Locks）は P3。
- **読み込み（import）**は封筒の `format`/`v` と各区画の版を反映前にすべて検証し、1つでも対応外なら何も変えずに失敗を知らせる。反映した読み込みは反映前の全区画の写しを持ち、トーストの「元に戻す」で戻す（review #1・#3）。値の検証（`st`/`rg` の min・max・step、`tm`・`dt` の形、`tx` の長さ、ID の重複・参照切れ）は UI・復元・import で同じ定義を使う（Zod に寄せる、review #4）。
- **大きな記録**（受け渡し・AIチャット・表・スクリプト・録音・画像変換）は localStorage に入れず、非同期の記録の保存先（IndexedDB、Dexie）を使う（最小限の境界はこの PR で対応中、review #7）。
- 保存キーは `lgd.v1:global` と `lgd.v1:w:<配置ID>`（実装ガイド 7.5 の区画）。プロトタイプの `lgdash.v1` は読まない（v0 からの移行もしない。ユーザー合意）。

### ウィジェット

- 1ウィジェット（種類）= `src/widgets/<kind>/`。`<Name>Widget.vue`（`WidgetFrame` で包む）、純粋な計算は `<kind>.ts`、記録は `data.ts`、テストは `<kind>.test.ts`、Storybook は `<Name>Widget.stories.ts`。
- テンプレートはプロトタイプの `<section data-w="<kind>">` の中身を、クラス名・aria-label・インラインの style を変えずに移す。`{{x}}` の値はプロトタイプの `renderVals()` / `xVals()` の計算をそのまま TypeScript に移す。
- 部品は**配置 ID を受け取り、`useWidget()` で自分の設定・記録だけを読む**（review #5、この PR で対応中）。ほかの区画や種類 ID の文字列（`'links'` など）を直書きで読まない。全画面・置かずに使う・前面表示でも同じ配置 ID の設定と記録を使う。
- 登録は実装ガイド 4章「登録の項目」をすべて埋める: `net`・`perm`・`priv`（人前では隠すの既定。仕様書 3章のリスト。`vd` とは別）・`states`・`refresh`・`run`（実行の寿命。下の「実行の寿命」）・`keys`・`store`。`icon` と `share` は値が決まるまで未定義でよい（review #6）。接続の点・状態の覆い・1×1 の知らせ・許可のお願いは共通の枠が登録から出し、ウィジェットで手で指定しない。
- **人前では隠すを最優先**にする。隠している間は、通常・前面表示・全画面・状態の覆い・1×1 の知らせのどれでも中身・読み上げ・中身のある知らせを出さない（仕様書 3章）。ただし**隠すことは止める理由にならない**: 判定と実行は続け、通知は共通の仕組みが伏せた文で出す（下の「通知」、schema v0 R15）。
- **表示の更新は表示中の画面だけ**。未配置・表示中でない画面・出ていない段は更新しない（仕様書 3章「段階表示」）。重いものは表示されるまで描画しない。古い非同期応答は捨て、unmount で部品が持つ timer などを止める（review #7）。これは表示（`refresh`）の決まりで、継続実行・監視は表示や unmount で止めない（下の「実行の寿命」）。
- 記録を変える操作の「元に戻す」は**個別**に持つ（共通の履歴は仕様書 7章の範囲だけ）。追加を戻すときは追加した行の ID だけを消し、ほかの編集は残す（review #3）。
- 見本データ（天気・PR・RSS など）はプロトタイプと同じ値を使い、`<kind>/sample.ts` に分ける。外部につなぐ部分は `adapter.ts` の境界だけ作る（P4 で差し替え）。**P4 まで見本・模擬で動くものは実際の機能と区別する**: `net: 'data'` の種類は接続の点（未接続の輪）で見本であることを示し、`dl`・`own` の模擬（ローカルAI・受け渡し）は実際のダウンロード・送信の成功として見せない。
- **未実装を成功扱いにしない**。登録だけあって中身が無い種類は、置く・置かずに使うと中身の置き換えで「準備中」を出し、追加の操作は「準備中です」と知らせて置かない（review #9、この PR で対応中）。
- 確認表（実装ガイド 4章）を満たす: 見出しの文字なし・読み上げ名あり、1×1 で破綻しない、色の直書きなし、押せるものは 44px 以上で button/a/input、Enter は変換中を除外、自動で動くものに止めるボタン、ライトとダークで読める、外部情報は5状態、消す操作に元に戻す。

### 実行の寿命（登録の `run`。p2a-followup.md 1章、schema v0 R14）

**配置・表示・実行は別の関心事。** ボードから外す・置き場所を変える・画面を移る・前面表示や全画面に切り替える・部品の unmount・一時利用を閉じる、を理由に実行を止めない。実行状態と期限は Dashboard の実行管理（`src/app/runtime/`）が持ち、種類ごとの処理（`Runner`）に委ねる。置き場所を移しても持ち主は変わらない。

**`run` の選び方**（`src/app/registry/registry.ts` の `RunLife`。表示の更新は `refresh` だけで書き、`run` に重ねない）:

| 種類の振る舞い | `run` | `refresh` | `Runner` | 例 |
| --- | --- | --- | --- | --- |
| 自分では動かない。入力・操作のときだけ変わる | `none`（受動） | なし | 書かない | TODO・メモ・クイックリンク |
| 見えている間だけ描く・取る・更新する。見えなくなったら止め、戻ったら追いつく | `none`（表示更新） | `{ every, visible: true }` | 書かない | 時計・世界時計・天気・傘・RSS・GitHub PR・カウントダウン・タイムスケジュール・タイムログ・打刻（勤務時間は記録から時刻の差で出す） |
| 明示して始め、止める・一時停止・完了まで続く。決まった時刻に完了・知らせがある | `continuous`（継続実行） | 残りを描き直すなら足す | 書く | ポモドーロ（描き直しは `refresh`、完了の判定は `Runner`） |
| 同上で、始めた時刻から計算でき、期限で何もしない | `continuous` | 描き直すなら足す | 書かない | ストップウォッチ |
| 設定でオン・接続してから、オフ・解除まで、期限やイベントを待つ | `watch`（時刻・イベントの監視） | 描き直すなら足す | 書く | アラーム（受け渡しの受信は P4） |
| 明示した Run から、終了・失敗・取消・上限まで。表示や配置で勝手に Run しない | `request`（要求実行） | — | 取り決めだけ（`RequestPhase`） | スクリプト・画像変換・翻訳・AIチャット（P2d・P2e、実処理は P4・#16） |

録音・ミュージック・環境音ミキサーも `continuous` だが、まだ作っていない。持ち方（音の要素を誰が持つか）は作るときに決める（[P2a の継続](./p2a-followup.md)「残したこと」）。

**`refresh` との分け方:**

- 描き直しは部品の中で、表示中だけ進む時計を使う（`src/widgets/shared/time.ts`）: 1秒ごとなら `useShownNow(d, id)`、細かい描き直し（ストップウォッチの 0.1 秒）なら `useFaceClock(d, id, active, ms)`。どちらも `drawnNow(d, id)`＝表示中（`isShown`）かつタブが前（`runtimeOf(d).page.shown`）のときだけ進み、それ以外は timer を持たない。
- 残り・経過・勤務時間は、終わる時刻・始めた時刻から計算する。1秒ごとに数えない（数えると、見えない間に止めたときに狂う）。
- 「見えていない間に何かが起きる」ことは `refresh` で書かない。それは `Runner` の期限。

**`Runner` を書くかの判断:** 見えていなくても・未配置でも、**決まった時刻に何かをする**（鳴らす・完了させる・知らせる）なら書く。計算で済むもの（ストップウォッチ・打刻）、表示中だけの更新、受動のものは書かない。46 種すべてを動かしたり、問い合わせ続けたりしない。

`Runner` の書き方（見本: `src/widgets/alarm/runner.ts`・`src/widgets/pomo/runner.ts`）:

1. `src/widgets/<kind>/runner.ts` に `Runner`（`start(ctx)`）を書き、`src/widgets/index.ts` の `WIDGET_RUNNERS` に種類 ID で登録する。`registry.test.ts` が、`WIDGET_RUNNERS` の種類の `run` が `continuous` か `watch` であることを確かめる。
2. 実行管理は Dashboard が動いている間、その種類の配置ごとに1回 `start` を呼ぶ（部品の mount とは関係なく、未配置でも）。配置が並びから消えたら（読み込み・元に戻す）止めて期限を取り消す。`start` は配置ごとの effect scope の中で動くので、設定・記録・実行 ID の変化は `watch(…, { immediate: true, flush: 'sync' })` で見て予定を立て直す。
3. 期限は `ctx.at(時刻, fn, sub?)`・`ctx.cancel(sub?)`。`Scheduler`（`scheduler.ts`）が一番早い期限に timer を1本だけ張り、期限が無くなれば放す。同じ key に入れ直す・取り消すと前の callback は呼ばれない。
4. **古い callback と二重の完了を防ぐ**: 期限の callback は作ったときの実行 ID（`rt.rid(id)`）を持ち、呼ばれたら今の実行 ID と比べて違えば何もしない。完了したら状態を変える（実行 ID が変わる）ので、2度目の完了は起きない。
5. **遅れた timer**: callback には呼ばれた時刻 `now` が渡る。判定はその時刻で行う。タブが裏から戻ったとき（`visibilitychange`）は実行管理が期限の来たものをすぐ判定し直す。**古すぎる期限の扱いを種類ごとに決めて書く**（アラーム: 1分より前に過ぎた分は鳴らさない＝`ALARM_LATE_MS`、過去の分をまとめて鳴らさない。ポモドーロ: 遅れても一度だけ完了）。OS が止まっている間・ブラウザを閉じている間に鳴ることは保証しない。
6. **担当のタブ**: 音・通知の前に `ctx.owns('<task>')` を見る（`OwnerLock`、`owner.ts`）。P2 は常に担当（2つのタブを開くと両方で鳴る）。担当決めは P3 の Web Locks。
7. **始めるのは明示の操作だけ**。mount・開き直し・一時利用を開くことで始めない（ポモドーロの `pomoGo` は動いていれば何もしない）。操作の関数は部品とテストで同じもの（`status.ts`・`actions.ts`）を使う。

**保存しない実行状態:** 実行状態（動いているか・終わる時刻・一時停止中の残り・経過の基準とラップ）は `runtimeOf(d).state(id, 既定)`・`set(id, 値)`（新しい実行 ID を返す）・`rid(id)` で持ち（`Runner` だけが使う覚え書き、例 アラームの最後に鳴らした分は `start` の中の変数でよい）、`cfg`/`data` に入れない（実装ガイド 6章）。種類ごとの読み書きは `src/widgets/<kind>/status.ts` に薄く置く（`pomoRunOf`・`setPomoRun`、`swOf`・`setSw`）。再読み込みで消える（ポモドーロとストップウォッチの進行。プロトタイプと同じ）。保存するのは利用者の設定（アラームの時刻＝`cfg`）と記録（アラームのスイッチ＝`data`）だけ。通知の許可の状態も保存しない。

### 許可のお願い（共通の仕組み。PR #25 で通知から広げた）

- 登録の `perm`（`geo`・`notify`・`mic`・`clipboard`）は、すべて `src/app/runtime/permission.ts` で扱う。種類ごとに許可のお願いを作らない。
  - `permOf(d, p)`: 許可の状態（`ok` / `no` / `''`）。Permissions API（通知は `Notification.permission`）から読み、保存しない。
  - `askPerm(d, id, p, { copy, then, request, alt })`: **明示の操作からだけ**呼ぶ。許可済みならすぐ `then`。まだなら共通の枠にカード（`permCover`）を出し、「許可」「もう一度」を押したときだけブラウザに問い合わせる。`request` を渡すと、操作そのもの（例: マイクを開く）を問い合わせの代わりにできる。
  - 断られたら、マイク・現在地・クリップボードはその操作だけをしない（「もう一度」と代わりの手段を出す）。通知は無くても続けられる。どの許可でも、ほかの実行（動いているポモドーロなど）は止めない。人前では隠している間はカードを出さない。
  - 文言はプロトタイプの文を既定（`PERMS[p].copy`）にし、種類は `AskCopy` で一部だけ重ねて渡す。
- 登録の `perm` と `states` の `'perm'` は一致させる（`registry.test.ts`）。

### 実行の後始末と実行中の一覧

- Runner を持たない継続実行（録音のマイクなど）は、`runtimeOf(d).onDispose(id, fn)` で後始末を登録する。呼ばれるのは**配置が並びから消えたとき（読み込み・元に戻す）と runtime を止めたとき**だけで、外す・置き場所の変更・画面の移動・前面表示・一時利用・unmount では呼ばれない。
- `active()` は継続実行の種類で実行状態が `on: true`（ストップウォッチは `run: true`）の配置を返す。新しい継続実行の種類は、実行中を `on: true` で表す。新しい版の帯の「再読み込み」はこれを使って、何が止まるかを確認する。

### 通知（共通の仕組み。p2a-followup.md 2・3章、schema v0 R15）

登録の `perm: ['notify']` を持つ種類（今はアラーム・ポモドーロ・ハビット）が対象で、`states` に `perm` を持つ。**種類ごとの専用の通知を作らない**: `Notification` を直接使う、独自のトーストや重複の判定を書く、`d.veiled(id)` を見て文を変える、種類の中に許可のカードを作る、はしない。

- **送る**: `Runner` の中なら `ctx.notify(msg)`、それ以外は `notify(d, id, msg)`（`src/app/runtime/notify.ts`）。`msg` は `{ key, text, title?, body?, kind? }`。`key` は1回の出来事ごとに一意にする（`alarm:<配置ID>:<i>:<鳴る時刻>`、`pomo:<配置ID>:<実行ID>`）。同じ key は1度しか出ない。戻り値（`off`・`dup`・`shown`・`veiled`）で実行を止めない。
- **基盤が受け持つこと**: 通知の設定（その種類の `tg` の項目 `notify`、例「完了を通知」。項目が無い種類は常にオン）、許可の状態（ブラウザから読む。保存しない）、人前では隠すの伏せ方、出し分け（画面の中は必ずトースト。ブラウザの通知はタブが裏にあって許可済みのときだけ。Web Push は使わない）、重複の防止。通知できるかどうかを実行できるかどうかにしない。
- **人前では隠すの伏せ方**（どの種類でも同じ文。ウィジェット名・時刻・内容を出さない）:

  | 出す場所 | 文 |
  | --- | --- |
  | アプリ内のトースト | 「通知があります。人前では隠すがオンなので、内容はウィジェットで確認してください」 |
  | ブラウザの通知・見出し | 「通知があります」 |
  | ブラウザの通知・本文 | 「人前では隠すがオンなので、内容はダッシュボードで確認してください」 |

  伏せたトーストは出ているあいだ重ねず、ブラウザの通知は同じ tag で置き換える。隠していないときは種類の文（「アラーム 07:00」「ポモドーロ完了」）。
- **許可のお願い**: 明示の操作（スタート、スイッチをオン）から `askNotify(d, id, { title, text, go? }, then?)` を呼ぶ。お願いを出すのは「通知の設定がオン・まだ答えていない・この配置で断っていない・隠していない」ときだけで、それ以外は `then` をすぐ呼ぶ。共通の枠（`WidgetFrame`）が `notifyCover()` を中身の置き換え（`cover`）に出す。ブラウザに問い合わせるのは「通知を許可」を押したときだけ。「通知しない」は、通知の設定の項目があればそれをオフにし、無ければこのセッションの間その配置に聞かない。断られた・対応していないときは「通知を出せません」と「このまま始める」を出し、実行は止めない（トーストだけで知らせる）。お願いの文は種類の `<kind>.ts` に置く（`POMO_ASK`・`ALARM_ASK`）。
- **設定パネルの一文**: 「ダッシュボードを開いている間だけ知らせます」（実装ガイド 7.2）は、`perm: ['notify']` の種類の設定パネルの最後に `NotifyOpenNote.vue` を設定シートが自動で出す。種類ごとに書かない。

### 時刻・乱数

テストで時刻を固定できるよう、時刻は `d.ui.t`（1秒ごとに更新）か `d.now()` から取る。`Math.random()` はプロトタイプで使っている所だけに限る。

### 機能・データのゲート（再現度とは別）

再現度テストは見た目だけを測る。**数値の再現度だけで合格にしない。** 保存・記録・登録に触れた変更は、次のテストを単体テストか e2e で持ち、通ること（[review-flow](./review-flow.md) 1章の 6）。

| 観点 | 確かめること |
| --- | --- |
| 往復 | 保存→復元、書き出し→読み込みで同じ状態に戻る。足りない項目は既定値で補い、知らない項目は捨てる |
| 負 fixture | 型・値域（`st`/`rg` の min・max・step、`tm`・`dt` の形、`tx` の長さ）・ID の重複・参照切れ・不正な数値・不正な封筒を既定値か失敗にする。外部入力は Zod で検証する |
| 保存 bytes の維持 | 未来の版・不正な区画・移行の失敗・import の失敗で、既存の記録と保存 bytes を変えない（書かない） |
| 区画の独立 | 変わった区画だけ書く。別の区画の変更が互いを消さない（2つの Dashboard が同じ保存先を使うテスト）。同じ種類の2つの配置 ID（`links` と `links#2`）が混ざらない |
| 版 | 区画の `v`/`dv` を書き、記録の形を変えたら `version` を上げて `migrate` を足し、古い版の fixture を置く |
| 保存しないもの | 実装ガイド 6章の除外（録音・画像変換の画像・現在地・スクリプトの結果・会話保存オフの会話など）と鍵・認証情報が保存・書き出しに入らない |
| 元に戻す | 共通の履歴は仕様書 7章の範囲。記録は個別の元に戻すで、関係ない編集を巻き戻さない。読み込みは元に戻せる |
| 結果を正しく言う | クリップボードやファイルの書き出しは、書けたことを確かめてから成功と言う。未実装・失敗を成功扱いにしない |
| 実行と通知（`run` が `continuous`・`watch` の種類、`perm: ['notify']` の種類） | 代表の場面（未配置、一時利用を閉じる・もう一度開く、置き場所の変更、画面の移動、人前では隠す、止める・リセット、期限の到来、タブが裏から戻る、再読み込み）で、止まらない・一度だけ完了する・二重に始まらない・古い callback が何もしないこと。timer を作る・放すこと。見えない間に描き直さないこと。実行状態が保存されず、設定と記録が保たれること。伏せた文に中身が出ないこと。見本: `src/app/runtime/{scheduler,runtime,notify}.test.ts`（部品を描かずに Dashboard と `WIDGET_RUNNERS` を fake timers で動かす `test-fixtures.ts`）、`e2e/time-widgets.spec.ts`「実行管理」 |

### 人間確認と公開の条件

P1 の確認・P2 の各分類の確認、公開（本番ビルドを人に渡す）の前に、次を確かめて記録する（review #9）。

1. 一覧は46種のまま見せる。**未実装の種類は「準備中」の置き換え**（印・見出し・説明）で出て、空白にならず、追加の操作が成功扱いにならない。公開では、未実装の種類が残っていないか、残すなら「準備中」であることを確かめる。
2. **プロトタイプ専用の機能が本番ビルドに出ない**（実装ガイド 付録「確認用の機能」: 全体設定の「表示テスト」、「すべて並べる」、画像変換の「見本で試す」、傘のウィジェット設定「サンプル」）。
3. **見本・模擬データで動くもの**（実装ガイド 付録「見本のデータと模擬の動き」）が実際の機能に見えない。外部の情報を取る `net: 'data'` の種類（天気・傘・RSS・GitHub PR・今日は何の日）は**接続の点（未接続の輪）で見本と示す**。ローカルAI（`net: 'dl'`）のダウンロードと応答、受け渡し（`net: 'own'`）の送信は、模擬を実際のダウンロード・送信の成功として見せない。
4. 人前では隠すで、通常・前面表示・全画面・状態の覆い・1×1 の知らせに中身が出ない。
5. ブラウザごとの結果を分けて記録する。Chromium の e2e と再現度テストの結果とは別に、**WebKit（Playwright）と実機 Safari（iPhone）の結果**を書く。確かめていないものは「未確認」と書き、合格扱いにしない。

### 共通の完了条件（各段階・各分類）

1. `npm run check` と `npm run build` が通る。
2. 追加・変更したシナリオの再現度テストが合格ライン以上。保存・記録・登録に触れたら、上の**機能・データのゲート**も通る。
3. 部品・ウィジェットに Storybook のストーリーがあり、Design Pattern Gallery に載っている。
4. 仕様の振る舞い（キー操作、元に戻す、空・失敗の状態など）に単体テストか e2e がある。
5. この文書と `docs/lgd/` の関係する資料を更新した。スキーマ v0 との食い違いを見つけたら `docs/widget-schema-v0.md` に理由つきで直した。
6. 確認・公開の前なら、上の「人間確認と公開の条件」を記録した。

## 6. 進め方の手順（1回分）

1. まとめ役が段階・分類を決め、層ごとのエージェントに「触ってよい場所」と正本の場所を渡す。
2. テスト実施層がシナリオを足し、プロトタイプから基準画像を作る。
3. ウィジェット層・UI/UX 層が実装する（プロトタイプの DOM と計算を移す）。
4. テスト実施層が再現度テストと単体・e2e を回し、判定層が合否と原因を出す。再現度の合否と、機能・データのゲート（単体・e2e の結果）の合否は別々に出し、片方だけで合格にしない。
5. 未達なら 3 に戻る。合格したら、まとめ役がコミットし、この文書の進み具合の表を更新する。
