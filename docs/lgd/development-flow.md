### 見た目の正本としての CSS

`src/app/styles/dashboard.css` はプロトタイプの `<style>` をそのまま移したもの。値を手で変えない。プロトタイプ側が変わったら丸ごと取り込み直す。クラス名（`.w` `.in` `.chip` `.nb` `.sheet` …）と DOM の形はプロトタイプと同じにする。こうすると再現度テストの差が小さくなり、部品シートとも対応がとれる。Vue のテンプレートは空白も描画に効くため、改行を足す整形系の lint ルールは切ってある（`eslint.config.mjs`）。

行の中に直書きされた `style="…"`（約440か所）は、まず**そのまま移す**。トークンとクラスへの置き換え（実装ガイド 9章）は、見た目が変わらないことを再現度テストで確かめながら P3 で行う。

## 3. 層と担当（エージェントの分け方）

ユーザー合意（2026-11-23）で、次の4層に分けて進める。層ごとに `.claude/agents/` にエージェント定義、`.claude/skills/` に手順を置く。

| 層 | 受け持つもの | 触ってよい場所 | エージェント / スキル |
| --- | --- | --- | --- |
| **判定層** | 合格ラインの判定、差分の原因の切り分け（どの部品・どの値か）、改善の指示書づくり。数値だけで合否を決め、主観で合格にしない | `vrt/report/`（生成物）、`docs/lgd/vrt-results.md` | `lgd-vrt-judge` |
| **テスト実施層** | 再現度テストのハーネスとシナリオ、基準画像の生成、Vitest の単体テスト、Playwright の e2e、Storybook の操作テスト | `vrt/**`、`e2e/**`、`*.test.ts`、`docs/lgd/vrt.md` | `lgd-vrt-runner` / スキル `lgd-vrt` |
| **ウィジェット実装層** | 各ウィジェットの中身、記録（data）の定義と検証、計算（必要なら `src/tools` の Operation） | `src/widgets/<id>/**`、`src/widgets/index.ts`、`src/tools/**` | `lgd-widget` / スキル `lgd-add-widget` |
| **UI/UX 実装層** | 土台（シェル）、部品、トークン、ストア、レイアウト、保存、Storybook、Design Pattern Gallery | `src/app/**`、`.storybook/**`、`src/gallery/**`、`gallery.html` | `lgd-ui-shell` |

同時に複数のエージェントが動くときは、**触ってよい場所が重ならないように**分ける。共有のストア（`src/app/store/store.ts`）に機能が要るときは、UI/UX 層に頼むか、ウィジェット側の `src/widgets/<id>/` に閉じた形で作る。コミットと push は親（まとめ役）だけが行う。

## 4. 作り方の決まり

### ストアと状態

- `Dashboard`（`src/app/store/store.ts`）が唯一の状態。部品は `useDash()` で受け取る。
- 状態は3つに分ける: `g`（区画「全体」に保存）、`cfg[id]` と `data[id]`（区画 `w:<id>` に保存）、`ui`（保存しない一時状態）。プロトタイプの `state` のキーはこのどれかへ移す。
- ウィジェットの記録は `WidgetDataDef`（`version`・`initial`・`sanitize`・必要なら `toSaved`）で定義し、`src/widgets/index.ts` の `WIDGET_DATA` に登録する。読み込み時は必ず `sanitize` を通し、知らない項目は捨てる。
- 保存キーは `lgd.v1:global` と `lgd.v1:w:<id>`（実装ガイド 7.5 の区画）。プロトタイプの `lgdash.v1` は読まない（v0 からの移行もしない。ユーザー合意）。

### ウィジェット

- 1ウィジェット = `src/widgets/<id>/`。`<Name>Widget.vue`（`WidgetFrame` で包む）、純粋な計算は `<id>.ts`、記録は `data.ts`、テストは `<id>.test.ts`、Storybook は `<Name>Widget.stories.ts`。
- テンプレートはプロトタイプの `<section data-w="<id>">` の中身を、クラス名・aria-label・インラインの style を変えずに移す。`{{x}}` の値はプロトタイプの `renderVals()` / `xVals()` の計算をそのまま TypeScript に移す。
- 見本データ（天気・PR・RSS など）はプロトタイプと同じ値を使い、`<id>/sample.ts` に分ける。外部につなぐ部分は `adapter.ts` の境界だけ作る（P4 で差し替え）。
- 確認表（実装ガイド 4章）を満たす: 見出しの文字なし・読み上げ名あり、1×1 で破綻しない、色の直書きなし、押せるものは 44px 以上で button/a/input、Enter は変換中を除外、自動で動くものに止めるボタン、ライトとダークで読める、外部情報は5状態、消す操作に元に戻す。

### 時刻・乱数

テストで時刻を固定できるよう、時刻は `d.ui.t`（1秒ごとに更新）か `d.now()` から取る。`Math.random()` はプロトタイプで使っている所だけに限る。

## 5. テストと合格ライン

| 種類 | 何を見るか | コマンド |
| --- | --- | --- |
| lint・型 | typed ESLint、`tsc`・`vue-tsc` | `npm run lint` / `npm run typecheck` |
| 単体 | レイアウト計算、保存の検証、各ウィジェットの計算（割り勘・税・日の出など） | `npm run test:unit` |
| 取り決め | `src/core` の Operation / JSON Schema の取り決め | `npm run test:contracts` |
| **再現度** | プロトタイプと本実装を同じ状態・同じ時刻（2026-11-19 10:24:36 JST）で撮って比べる | `npm run vrt:baseline`（基準の生成）／`npm run vrt`（比較） |
| e2e | 操作の流れ（画面送り・シート・元に戻す・保存と復元） | `npm run test:e2e` |
| Storybook | 部品の状態の見本と操作の確認 | `npm run storybook` / `npm run build-storybook` |

**再現度の合格ライン（ユーザー合意）: 1画面ごとに SSIM ≥ 0.95 かつ 差分画素率 ≤ 5%。** 未達のシナリオは判定層が原因を切り分け、UI/UX 層かウィジェット層が直し、合格するまで繰り返す（回数の上限は置かない）。シナリオの一覧と結果は `docs/lgd/vrt.md` と `docs/lgd/vrt-results.md`。

`design/claude-design/gallery/*.webp` の12枚はプロトタイプの古い版から撮られたもので、メモの先頭や受け渡しの帯が現行版と違う。合否はプロトタイプ現行版から作った基準画像で決め、12枚との数値は参考としてレポートに残す。

### 共通の完了条件（各段階・各分類）

1. `npm run check` と `npm run build` が通る。
2. 追加・変更したシナリオの再現度テストが合格ライン以上。
3. 部品・ウィジェットに Storybook のストーリーがあり、Design Pattern Gallery に載っている。
4. 仕様の振る舞い（キー操作、元に戻す、空・失敗の状態など）に単体テストか e2e がある。
5. この文書と `docs/lgd/` の関係する資料を更新した。スキーマ v0 との食い違いを見つけたら `docs/widget-schema-v0.md` に理由つきで直した。

## 6. 進め方の手順（1回分）

1. まとめ役が段階・分類を決め、層ごとのエージェントに「触ってよい場所」と正本の場所を渡す。
2. テスト実施層がシナリオを足し、プロトタイプから基準画像を作る。
3. ウィジェット層・UI/UX 層が実装する（プロトタイプの DOM と計算を移す）。
4. テスト実施層が再現度テストと単体・e2e を回し、判定層が合否と原因を出す。
5. 未達なら 3 に戻る。合格したら、まとめ役がコミットし、この文書の進み具合の表を更新する。
