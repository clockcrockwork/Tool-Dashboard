# P2a の継続：実行の寿命・通知・打刻の作り直し

作成: 2026-11-27。PR #23（P2a 時間）への利用者の決定をまとめ、#23 の続きの作業と P2b 以降の共通の取り決めを決める。

出典:
- PR #23 コメント（2026-11-27「P2a 継続指示：配置・表示・実行ライフサイクルの分離（ユーザー決定）」）
- 同日のチャットでの回答（下の 2〜4 章）

## 1. 配置・表示・実行を分ける（PR #23 コメント、確定）

- **ボードから外すのは、止めることでも消すことでもない。** 一時利用と通常の配置は、同じ配置 ID の設定・記録・実行状態を使う。次のことを理由に、機能を勝手に止めない。
  - 置き場所を変える、画面を移る
  - 前面表示・全画面に切り替える
  - 部品を unmount する、一時利用を終える
  
  ただし、表示中だけ更新する機能は、見えない間は更新を止めてよい。
- 次の6つは別の関心事として扱う。
  - 表示（今の画面・前面表示・人前では隠す）
  - 配置（off・place・大きさ・固定）
  - 実行状態
  - 通知の設定と許可
  - 利用者の設定
  - 利用者の記録
  
  通知の設定は cfg に保存してよいが、通知できるかどうかを実行できるかどうかにしない。同じものを二重に保存しない。
- **実行状態と予定の管理は Dashboard（アプリ共通の基盤）が持つ。** 種類ごとの処理はそこへ委ねる。置き場所を移しても持ち主は変わらない。配置 ID・区画と `useWidget(id)` の考え方はそのまま使う。

### 登録に足す「実行の分類」

既存の `refresh`（表示中の更新の間隔と条件）はそのまま残し、**実行の寿命と開始の条件**は別の項目で宣言する。表示の更新は `refresh` だけで表し、実行の項目に重ねて書かない。

| 分類 | 実行・更新の条件 | 代表 |
| --- | --- | --- |
| 受動 | 自分では動かない。入力・操作のときだけ変わる | TODO、メモ、リンク |
| 表示更新 | 見えている間だけ描く・取る・更新する。見えなくなったら止め、もう一度見えたら追いつく（`refresh` で表す） | 時計、世界時計、天気、傘、RSS、GitHub PR、カウントダウン |
| 継続実行 | 明示して始めてから、止める・一時停止・完了まで。配置と表示に関係しない | ポモドーロ、ストップウォッチ、録音、音楽、環境音 |
| 時刻・イベントの監視 | 設定でオン・接続してから、オフ・解除まで。期限やイベントを待つ | アラーム、受け渡しの受信 |
| 要求実行 | 明示した Run から、終了・失敗・取消・上限まで。表示や配置で勝手に Run しない | スクリプト、画像変換、翻訳、AI の生成 |

- 表示更新と実行は組み合わせてよい。例: ポモドーロの残り時間の描き直しは `refresh`、完了の判定は継続実行。
- 打刻の勤務中かどうかは、記録から時刻の差で出すので常時の処理は要らない。
- まだ作っていない分類は、取り決めと模擬の境界だけ用意する。

### 基盤の作り
- 汎用のキュー・Worker・常駐プロセスは作らない。**次の期限に合わせた timer と実行 ID の管理**だけの最小のスケジューラを Dashboard に置く。
- 必要な機能だけを動かす。46 種すべてを常に mount したり、問い合わせ続けたりしない。開始時刻から計算できるもの（ストップウォッチ）は、見えない間は時を刻まない。
- 実行状態は cfg/data に自動で保存しない（実装ガイド 6章）。ポモドーロとストップウォッチの進行は、再読み込みで消える今の仕様のまま。アラームの設定は保存する。
- OS が止まっている間やブラウザを閉じている間に鳴ることは保証しない。タブが裏に回って timer が遅れたら、戻ったときに時刻から判定し直す。古すぎるアラームの扱いを明示し、過去の通知をまとめて鳴らさない。
- 複数のタブのどれが担当するかは、P3 の Web Locks につなぐための取り決めだけ用意する。
- 実行中の機能は、一時利用や一覧など今ある入口から、もう一度確かめたり止めたりできる。新しい UI が要るなら別に提案する。

### 種類ごとにすること
| 種類 | すること |
| --- | --- |
| アラーム | オンの設定があれば、未配置でも部品を描いていなくても、Dashboard が動いている間は見張る。オフにすれば止める。設定を変えたら予定を立て直す。期限を過ぎたときは判定し、二度鳴らさない |
| ポモドーロ | 一時利用で始めて、閉じても・未配置でも、期限が来たら同じ実行が一度だけ完了する。開き直しても二重に始まらない |
| ストップウォッチ | 見えなくても、経過の基準時刻を持ち続ける。見えない間に細かく描き直さない |

## 2. 人前では隠すと通知（チャットの回答 1、確定）

- 人前では隠すは、ウィジェットを止めてよいという意味ではない。**隠している間も判定と実行は続け、通知も出す。中身は伏せる。**
- 文言は、どの種類でも同じものにする。

  | 出す場所 | 文言 |
  | --- | --- |
  | アプリ内のトースト | 「通知があります。人前では隠すがオンなので、内容はウィジェットで確認してください」 |
  | ブラウザの通知・見出し | 「通知があります」 |
  | ブラウザの通知・本文 | 「人前では隠すがオンなので、内容はダッシュボードで確認してください」 |

  ウィジェット名・時刻・内容は出さない。
- 隠していないときは、今どおり種類ごとの文で知らせる（例「アラーム 7:00」「ポモドーロ完了」）。

## 3. 通知は共通の仕組みにする（チャットの回答 2、確定）

- 予定など、通知が欲しい道具はほかにもある。だから**通知は種類ごとの専用の仕組みにせず、共通の仕組みにする**。アラームにも許可のお願いを出す。
- 登録の `perm: ['notify']` を持つ種類が対象。種類は送る内容を渡すだけにし、次のことは基盤が受け持つ。
  - 通知の設定（cfg、例「完了を通知」）の確認
  - 許可の状態（Permissions API。保存しない）の確認
  - 人前では隠すの伏せ方（2章）
  - アプリ内のトーストとブラウザの通知の出し分け
  - 重複の防止
- 許可のお願いは、共通の枠の置き換え（`cover`）で出す。必ず明示の操作（「許可する」を押す）に結びつける。断られた・対応していないときも、実行は止めない（トーストだけで知らせる）。
- 通知が開いている間だけ届くことの一文（実装ガイド 7.2）は、通知を使う種類の設定パネルに共通の部品で出す。

## 4. 打刻を作り直す（チャットの回答 3、確定）

プロトタイプの打刻（日ごとの出勤・退勤、全期間の合計）を、次の考えで作り直す。**見た目はプロトタイプの部品と配色の範囲で作り、変わった画面は `deferred.md` に記録する。**

1. **出勤から退勤までを1つのセッションにする。** 日付で区切らないので、夜勤（日をまたぐ勤務）もそのまま1セッションになる。
2. **業務の種類を選べる。**
   - 本業・副業など。選択チップ（`.tgts .chip`）のように並べる。
   - 利用者が自由に足せる。
   - 既定は前回選んだ種類。
   - 出勤するとき、その種類でセッションを始める。退勤はそのセッションを閉じる。
3. **集計は出勤の時刻で決める。** 例: 月の集計では、出勤の時刻がその月に入っているセッションを数える。今月と今日の合計を出す。
4. **タイムログへの記録**（「タイムログにも記録」）は今どおり。行の文に業務の種類を入れる。元に戻すは、足した行だけを戻す。
5. **記録の版を上げる**（v1 → v2）。v1 の記録（打刻の並び）は、出勤と退勤の組からセッションに移す。種類は既定の1つ目にする。移せないものは移行の失敗とし、区画を残す（review #1 の規則）。

決めること（作るときに決めて、報告と資料に書く）: 種類の初期値（例 本業・副業）、セッションの上限の件数、出勤したまま退勤していないときの見せ方、種類を消したときにその種類のセッションをどう扱うか（種類は消せるが、セッションの種類名は残す、など）。

## 5. 進め方

| 担当 | すること | 触る場所 |
| --- | --- | --- |
| UI/UX 実装層（基盤） | 登録の「実行の分類」、Dashboard のスケジューラと実行管理、共通の通知（許可のお願い・人前では隠すの伏せ方）。アラーム・ポモドーロ・ストップウォッチをこれに移す | `src/app/**`、`src/widgets/{alarm,pomo,stopwatch,shared}/**` |
| ウィジェット実装層 | 打刻の作り直し（セッション・業務の種類・集計・記録の移行） | `src/widgets/punch/**`、タイムログへの記録の部分 |
| テスト実施層 | 打刻の見た目が変わる分の再現度テストの扱い（打刻の範囲を両方で覆い隠して比べる）と、e2e | `vrt/**`、`e2e/**` |
| 資料 | 登録の項目・正本・開発フロー・`lgd-add-widget` に、実行の分類・通知・保存の判断を足す | `docs/**`、`.claude/**` |

完了の条件（PR #23 コメントの完了条件）:
- **代表 fixture:** 次の場面を足す。未配置、一時利用を閉じる・もう一度開く、置き場所の変更、画面の移動、人前では隠す、止める・リセット、期限の到来、再読み込み。
- **timer:** 作ることと放すこと、古い callback と二重の完了を防ぐことを確かめる。
- **見えないとき:** 取得・描画が止まることを確かめる。
- **保存:** 設定と記録が保たれることを確かめる。
- **ゲート:** check・build・e2e・再現度テストを通し、まだ試していない環境と、残る P3/P4 の制約を記録する。

その後、P2b（予定と記録）へ進む。予定は通知が欲しい種類の候補なので、3章の共通の通知を使う。
