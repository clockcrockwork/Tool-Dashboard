リキッドグラス・ツールダッシュボード

実装ガイド

プロトタイプ Main.dc.html を本実装に引き継ぐための資料です。トークン、ウィジェットの登録と作り方、保存、作りの土台、標準への対応、機能ごとの実装要件をまとめています。

何をするか・どう振る舞うかは「仕様書」（Spec.dc.html）、部品の見た目と状態は「部品シート」（Parts.dc.html）が正です。色や寸法の細かな値はプロトタイプを正とし、食い違いを見つけたら資料を直してください。

ダッシュボードに戻る

1. 層の考え方

画面は3つの層でできています。層をまたいで素材を混ぜないことが、見た目の落ち着きを保つ条件です。

層中身素材影
壁紙輪郭のある大きな色面不透明。動かさないなし
内容（ウィジェット）各ツールの面と、その中の操作部品薄く色づいた面＋背景ぼかし。縁は左上と右下だけ光る接地する小さな影
操作（バー・シート・トースト）画面切替、設定、通知バーは透明度の高いガラス。シートとトーストは文字が主役なので濃い面浮いて見える大きめの影
  • ガラスの上にガラスを重ねません。ウィジェットの中の部品は --fill 系の塗りで作ります。
  • ウィジェットに斜めの照りや大きな落ち影を付けません。浮いて見える原因になります。
  • 縁で背景が歪む屈折表現は未実装です。入れる場合は下部バーに限り、対応しないブラウザではぼかしに落とします。

3. 見た目を作り直すためのレシピ

ここにある値をそのまま使えば、プロトタイプの面と層を再現できます。色はすべて2章のトークンです。

ウィジェットの面

.w {
  position: relative; overflow: hidden;
  border-radius: var(--rad);            /* 26px */
  container-type: size;                 /* 中身を面の寸法に比例させるため */
  background: var(--glass);
  backdrop-filter: blur(var(--blur)) saturate(180%);
  box-shadow:
    var(--rim),                         /* 全周の薄い縁と外側の極細の輪郭 */
    var(--el1);                         /* 接地の影と広がる影 */
}
.w::before {                            /* 左上と右下だけ光る縁 */
  content: ""; position: absolute; inset: 0;
  border-radius: inherit; padding: 1.25px; pointer-events: none;
  background: linear-gradient(135deg,
    var(--hi) 0%, transparent 26%, transparent 70%, var(--hi3) 100%);
  mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  mask-composite: exclude;              /* 枠の部分だけ残す */
}

下部バー（操作の層）

.nav {
  background: var(--glass2);
  backdrop-filter: blur(9px) saturate(190%) brightness(1.06);
  box-shadow: var(--rim), var(--el2);
}
.nav::after {                           /* 縁5pxの帯だけ、背後を明るく鮮やかに */
  content: ""; position: absolute; inset: 0;
  border-radius: inherit; padding: 5px; pointer-events: none;
  backdrop-filter: blur(1.5px) saturate(230%) brightness(1.16);
  mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  mask-composite: exclude;
}

シートとトーストは --sheet の面に同じ影の考え方（シートとダイアログは --el3、トーストは --el2）で、背景ぼかしは 26〜30px です。

壁紙と全画面の時計

  • 壁紙は円の色面4つを固定位置に置きます。中心と半径は、(15%, 22%) 26vmin、(86%, 30%) 20vmin、(40%, 60%) 11vmin、(63%, 98%) 34vmin。輪郭は2pxだけぼかします。画面を送っても壁紙は動きません。
  • 全画面の時計は、地の色の上に、5色の斜めグラデーションで塗った円8個を置き、ぼかし（標準偏差30）と不透明度の引き締め（係数28、切片−12）で円同士をつなげます。グラデーションは画面基準で固定し、円だけを15〜31秒周期で往復させます。表示中の画面でだけ動かします。
  • 時計は面の幅の31%か高さの52%の小さいほう、太さ200。

4. 新しいウィジェットを足す手順

  1. 役割を1文で書く。 「何を一目で見せ、何を1操作でさせるか」。2つ以上の役割があるなら分けます。
  2. 主役を決める。 数字、図、リスト、入力のどれが主役かを決め、仕様書4章の部品から選びます。既存の部品で表せないときだけ新しい部品を作り、この資料に追記します。
  3. 既定の大きさを決める。 下の目安に従い、1×1でも破綻しないかを確認します。
  4. 登録する。 下の「登録の項目」を埋めて登録表に足し、初期の置き場所（ボード）を決めます。
  5. 面の中身を書く。 下の骨組みから始めます。
  6. 保存するものを決める。 利用者が入力したものは保存対象の一覧に足します（6章）。
  7. 確認表を通す。

大きさの目安

中身既定
数字1つ、ボタン1つ1×1
数字＋補足、横一列の操作、3要素の型2×1
横に長い時間軸や7列3×1 か 4×1
3〜5行のリスト、入力＋リスト、操作盤2×2
グラフ＋凡例、横に並ぶ2つの領域3×2
縦に長いリストやキーの並び2×3

通信と許可の出し方

登録の net と perm があれば、ツールの中身に関係なく次の場所に出します。ツール側で別の出し方を作りません。

登録出すもの場所
net: 'data'接続の点（未接続は輪、オフラインは塗り）と、読み上げ用の文面の右上（全画面では .fsw-act）
net: 'data' ＋オフライン前回の内容をそのまま出し、点を塗る。前回の内容が無ければ「失敗」の知らせ（仕様書3章）面の中
net: 'dl'はじめてのダウンロードの帯（大きさと「準備する」）。押すまで通信しない面の上端の帯
net: 'own'つながりの状態をツール自身の文で出す（受け渡しの「2台とつながっています」など）。接続の点は出さないツールの中
perm許可のお願い（何のために要るかを1文＋「許可する」）。断られたら、使える範囲で動かして理由を出す面の中身と置き換え。1×1 はトースト（仕様書3章）

骨組み

登録（1行）。n は表示名、s は既定の横×縦、f は固有設定です。ほかの項目は上の表のとおりです。全画面で出せるものは pg: true を足し、全画面用の表示を上の共通の形（仕様書2章）で用意します。

stretch: {
  n: 'ストレッチ', cat: '時間', kw: 'すとれっち 体操', s: [2, 1], min: [1, 1], perm: ['notify'],
  f: [ { k: 'notify', t: 'tg', l: '完了を通知', d: true } ]
}

面の中身。外側の section と内側の .in は全ウィジェット共通で、変えません。

<section class="w" data-w="stretch" aria-label="ストレッチ">   ← 配置は grid-area で外から与える
  <div class="in" style="align-items: center; gap: 14px">      ← 内側余白14pxの入れ物
    <div class="num" style="font-size: min(48cqh, 23cqw); font-weight: 300">05:00</div>
    <button class="btn on" aria-label="スタート">…アイコン…</button>
  </div>
</section>

確認表

  • 見出しの文字を置いていない。読み上げ用の名前は付いている。
  • 1×1に縮めても、主役が読めるか、切り落とされて害がない。
  • 色を直書きしていない。--a1 で塗った要素は1つだけ。
  • 押せるものはすべて44px以上で、button か a か input。
  • アイコンだけのボタンに名前がある（ツールチップにそのまま出ます）。
  • 入力欄の Enter は変換中を除外している。入力中のキーが画面切替に漏れない。
  • 自動で動く・鳴るものに止めるボタンがある。
  • ライトとダークの両方で、補助文字が読める。
  • 外部の情報を使うなら5つの状態（通常・読み込み中・更新中・空・失敗）を用意した。利用者が書きためるものなら空の状態を用意した。
  • 消す操作に「元に戻す」がある。

5. データと保存

  • 保存先はブラウザ内（localStorage のキー lgdash.v1）。保存するのは、配置（ボード、並び順、大きさ、未配置）、全体設定、ウィジェット設定、利用者が入力した記録（TODO、メモ、タイムログ、打刻など）です。
  • 書き出しは同じ内容を1つのJSONとして渡し、読み込みは項目ごとに検証してから反映します。知らない項目は捨て、足りない項目は既定値で補います。
  • 形式を変えるときはキーの版を上げ、旧版からの移行を用意します。更新で記録が消えることを最優先で避けます。
  • 本実装で外部サービスにつなぐ場合、接続はウィジェットごとに利用者が明示的に行い、鍵や認証情報は書き出しに含めません。
  • 書き出しは「コピー」と「ファイルに保存」（dashboard-年月日.json）の2つ。最後に書き出した日を全体設定に出し、30日たったら一度だけトーストで知らせます（同じ知らせは7日あける）。
  • 保存に失敗したとき（容量不足など）は黙らず、理由と「ファイルに保存」をトーストで出します。

7. 作りの土台で決めたこと

7.1 配り方

  • URL で公開する版と、GitHub でソースを公開して各自が立てる版の2つ。スマホは PWA としてホーム画面に置いて使う前提にします。
  • 新しいタブを置き換える拡張機能としては配りません。ポップオーバーやサイドパネルに出す拡張機能版は、作る場合も別の包みとして扱います。
  • URL の版では、PC の新しいタブにはそのままではなりません。ブラウザの「起動時に開くページ」や「ホームページ」に設定する案内を、全体設定の操作ヒントに置きます。開いた直後の検索欄へのフォーカスは、普通のページとして開くので効きます。
  • URL の版で外すか条件付きにする機能: 外部の情報を取りに行くもの（RSS はブラウザから直接読めないサイトが多く中継が要る、GitHub は認証が要る、天気は取得先の利用条件による）、受け渡しの中継。自分で立てる版は、取得先や中継のURLを設定で変えられるようにします（仕様書9章）。

7.3 タブやウィンドウを何枚も開いたとき

同じダッシュボードを何枚も開き、それぞれで別の画面を表示する使い方を正式に扱います。

  • 今見ている画面はタブごとに持ち、保存しません。URL の #p=番号 でタブごとの画面が残ります（仕様書2章）。
  • 保存した内容が別のタブで変わったら、storage イベントで受け取り、すぐ画面に反映します。ただし、いま入力している欄の項目（メモを書いている間のメモなど）と、設定パネルで編集中の項目は上書きしません。
  • 同時に1つだけ動けばよいもの（アラームの音と通知、受け渡しの受信と既読、AIモデルの読み込み、中継サーバーへの接続）は、Web Locks API で担当のタブを1枚に決め、閉じたら別のタブが引き継ぎます。
  • 本実装では、保存を項目ごとに分けて（IndexedDB の項目単位）、同時に書いても互いを消さないようにします。プロトタイプは全体を1つで保存し、変わった内容をほかのタブへ配るところまでです。
  • 「元に戻す」の履歴はタブごとです。ほかのタブから届いた変更は、このタブの履歴に積みません。

7.4 同じ種類を複数置く

置けるかどうかはウィジェットによるため、保存の形は最初から複数前提にします。

  • 置いた1個ごとに ID（例: links#2）を持ち、設定・記録・位置・大きさはその ID で持ちます。登録表には種類ごとに「複数置けるか」を持たせます。
  • 「ウィジェットを追加」では、複数置ける種類は置いてあっても ＋（ここにも置く）を出し、1つだけの種類は今の ↓（移動）のままにします。
  • 記録を共有するか（同じTODOを2か所に出すか、別のTODOにするか）は種類ごとに決めます。既定は別々にします。
  • 全画面は大きさの1つなので、置いた1個ごとに選べます（時計を2つ置いて、片方だけ全画面にするなど）。全画面にするために同じ種類を2つ置く必要はありません。
  • プロトタイプは1種類1個の保存の形で、複数置くことには対応していません。

7.5 保存先

  • 設定は localStorage、画像（受け渡し、項目の画像）、会話、表、スクリプトなど大きくなるものは IndexedDB に分けます。
  • 保存の永続化（navigator.storage.persist()）を記録全体に求めます。
  • 本実装では保存のキーを区画に分けます。全体（ボード、置き場所、並び順、全体設定）と、置いた1個ごとの区画（w:<ID> に設定 cfg と記録 data）です。プロトタイプは全部を1つの並びで持っていて（6章）、ツールを足すたびに全体のキーが増える形です。これをやめ、ツールは自分の区画だけを読み書きします。
  • 区画には版番号を持たせ、形を変えるときは読み込み時に移し替えます。外したウィジェットの区画は残し、「元に戻す」と書き出しの対象にします。
  • Safari などの WebKit 系では、サイトを使わない期間が続くとスクリプトで書いた保存が消されることがあります。書き出しの知らせ（5章）で備えます。

9. 機能ごとの実装要件

仕様書の各章のうち、本実装で足す・作り直すものです。

画面の行き来（仕様書7章）

  • シートや前面表示を開くたびに履歴に1件積み、ブラウザとスマホの「戻る」で1枚閉じるようにします。画面上の「戻る」で閉じたときは、積んだ履歴も1件戻して数を合わせます。プロトタイプでは未実装です。
  • シートとダイアログを開いている間は、キーボードのフォーカスをその中に閉じ込め、閉じたら開いたボタンへ戻します。

ローカルAI（仕様書8章）

  • モデルは Cache Storage か OPFS に保存し、保存領域の永続化（navigator.storage.persist()）を求めます。保存の前に空き容量（navigator.storage.estimate()）を確かめ、足りなければダウンロードを始めずに伝えます。
  • モデルのファイルは整合性を確かめてから使います。
  • しばらく使わなければモデルをメモリから外します（目安10分）。外したあとは「停止中」の状態に戻ります。
  • オフラインでも、保存済みのモデルなら使えます。未準備のままオフラインなら、準備ボタンを無効にして理由を出します。
  • 応答は事実と異なることがあります。初回の応答の前に一度だけ、その旨を短く伝えます。

受け渡し（仕様書9章）

  • 鍵はブラウザ標準の暗号機能で作り、書き出し（5章）には含めません。端末を移すときはペアリングし直します。
  • 中継サーバーが預かる暗号文には期限（24時間）と上限（1件あたりの大きさ、件数）を設けます。
  • LocalSend の Web 用シグナリングへの参加は、LocalSend のプロトコルの版に合わせて作り、対応する版を設定に表示します。
  • テキストは受信時にHTMLとして解釈せず、URLは http/https 以外を開きません。

部品の直し

  • 重なりの順を数字の直書きから層のトークンにする（3章の「重なりの順」）。
  • 小さなチップ（.chip.sm）の縁を --line にして 3:1 以上にする。
  • 選択の並びを選択メニューにする基準を、選ぶものの数だけでなく、シートの幅に入るかでも判断する（全体設定の「検索先」など）。
  • 行の中に直接書いた見た目（style 属性、プロトタイプで約440か所）を、部品シートのクラスとトークンに置き換える。

付録. プロトタイプだけにあるもの

本実装には入れないもの、または見本として置いているものです。

確認用の機能（本実装に入れない）

  • 全体設定の「表示テスト」: オフライン、状態（読み込み中・更新中・空・失敗）を天気・GitHub PR・RSS に当てる、お知らせと削除の確認のダイアログ、受け渡しの受信の模擬、新しい版の帯、画面の切り欠き（上59px・下34px）、案内の環境の切替（自動・PC・iPhone・Android・アプリ）。
  • 全体設定の「すべて並べる」: 全ウィジェットを4ボードに並べた見本の構成。
  • 画像変換の「見本で試す」: 時間で模擬した4件を足す。
  • 傘のウィジェット設定「サンプル」: 降り方を3通りに切り替える。

見本のデータと模擬の動き

  • 天気、予定の初期値、PR、RSS、グラフの数値、メーターはサンプルです。「今日は何の日」は11月17日分だけです。天気の段は約1秒の下書きのあとに出す模擬です。
  • 音楽プレイヤーは音を出しません。環境音はその場で合成した簡易なノイズです。
  • 受け渡しは送信で一覧に足すだけです。QRコードは見た目だけで読み取れません。
  • 翻訳とAIチャットは、ダウンロードと読み込みを時間で模擬し、決まった文を流します。
  • スクリプトはブラウザの中でそのまま動きます（実行環境の分離はありません）。外から貼ったコードは動かさないでください。
  • 検索は Google の結果を新しいタブで開きます。新しいタブとして使う本実装では同じタブで移動します。

プロトタイプで作っていない範囲

  • メモのMarkdownは一部だけです（入力中の色分けは行頭の記号、プレビューは太字・コード・区切り線まで）。リンク、表、入れ子のリストは本実装で範囲を決めます。
  • 録音は保存せず、再読み込みで消えます（最大6件）。項目の画像は96pxにして設定と一緒に保存しています（本実装は IndexedDB に分ける。7.5）。
  • 定型ボタンの文言（タイムログ、TODO）は固定です。ドラッグでの並べ替えはありません。ボードは通し番号で、改名はありません。
  • ブラウザやスマホの「戻る」との連動、ダイアログの <dialog> 化、上下の帯をウィジェットの領域の外に出す処理はありません（仕様書7章、8章）。
  • 同じ種類の複数配置（7.4）、PWA のマニフェストと Service Worker（7.2）、IndexedDB への保存（7.5）はありません。
  • 検索の「新しいタブで開く」は、プロトタイプでは既定をオンにしています（画面の確認中に表示が移動しないように）。
  • 描画は目で確認しないまま組んでいます。実装前に、主な画面幅（390、768、1280、1440）とライト・ダークの両方で表示を確認してください。
