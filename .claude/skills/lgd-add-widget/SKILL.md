# ウィジェットを1つ足す

前提: `docs/lgd/development-flow.md`（特に 4章「作り方の決まり」の「実行の寿命」「通知」と 5章「機能・データのゲート」）、`docs/lgd/review-flow.md` 2章の表（決定済みの方針）、`docs/lgd/p2a-followup.md`（配置・表示・実行を分ける、共通の通知）を読んでいること。対象の種類 `<kind>` は `src/app/registry/registry.ts` に登録済み（新しい種類なら実装ガイド 4章「新しいウィジェットを足す手順」で登録から始める）。

ブラウザの画面とデータは `design/claude-design/` と `docs/lgd/` が正本。`docs/tool-module-contract-v2.md`・`docs/quality-gates-v2.md` の placement / instance / `standalone:<kind>` / 削除の三択 / revision は使わない（各文書冒頭の「適用範囲」）。

下の「この PR で対応中」は PR #22 のレビュー対応で土台に入る予定のもの。土台にまだ無ければ自分で作らず、UI/UX 実装層への依頼として報告に書く。

1. **プロトタイプの範囲を探す**
   - マークアップ: `grep -n 'data-w="<kind>"' design/claude-design/Main.dc.html`（`<section class="w ...">` から `</section>` まで）。
   - 値: スクリプトの `renderVals()` と `xVals()` で、テンプレートの `{{...}}` に使われている名前を grep する。初期データは `D()`、ウィジェット固有の操作はメソッド（`calc` `trRun` など）。
   - 仕様: 仕様書 3章「登録済みウィジェット」の行と、そのウィジェットの章。部品シート 9章・12章に見本があればそれも。実装ガイド 6章で、そのウィジェットの記録が保存対象か・除外か。
2. **ファイルを作る**（`src/widgets/<kind>/`）
   - `<Name>Widget.vue`: `WidgetFrame` で包み、`.in` 以下はプロトタイプのマークアップをクラス名・aria-label・style を変えずに移す。`{{x}}` は computed に。
   - `<kind>.ts`: 純粋な計算。`<kind>.test.ts`: その単体テスト（境界値・空・失敗）。
   - `data.ts`: 記録があれば `WidgetDataDef`（version / initial（プロトタイプの初期値）/ sanitize / toSaved / 形を変えたら migrate）。
   - `sample.ts` / `adapter.ts`: 外部の情報を使うなら見本データと差し替えの境界。
   - `status.ts`: 保存しない実行状態の読み書き（`runtimeOf(d)` の薄い包み）と、部品とテストで共有する操作。`actions.ts` に操作だけを分けてもよい。
   - `runner.ts`: 見えていなくても決まった時刻に何かをする種類だけ（下の「実行の寿命」）。
   - `<Name>Widget.stories.ts`: 通常・1×1・各状態（読み込み中・更新中・空・失敗・人前では隠す）。
3. **登録する**: `src/widgets/index.ts` の `WIDGETS`（必要なら `FULLSCREEN`）と `WIDGET_DATA`、`Runner` があれば `WIDGET_RUNNERS`。種類 ID がキー。
4. **チェック（データと契約）**: 下の「チェック」を1つずつ満たし、満たせないものは理由と段階（P3・P4・未決定）を報告に書く。
5. **確認表**（実装ガイド 4章）を1つずつ満たす。
6. **再現度テスト**: `vrt/scenarios` にそのウィジェットを置いた状態（seed で `off` から外す）・小型・状態のシナリオを足し、`npm run vrt:baseline -- --only <scenario>` → `npm run vrt -- --only <scenario>`。合格ライン（SSIM ≥ 0.95・差分率 ≤ 5%）未達なら差分画像を見て直す。
7. **機能・データのゲート**（開発フロー 5章）: 記録や登録に触れたら、往復・負 fixture・保存 bytes の維持・区画の独立・版のテストを足して通す。再現度の数値だけで合格にしない。
8. `npm run check` と `npm run build`。
9. Design Pattern Gallery（`src/gallery/`）の「9. ウィジェットの表示」に載せる。

## チェック

### 登録の項目（実装ガイド 4章「登録の項目」）

登録（`src/app/registry/registry.ts`）は UI/UX 実装層の持ち物。ウィジェット実装層は値を決めて確かめ、直す必要があれば UI/UX 層に頼む。

- [ ] `n` `cat` `kw` `s` `min` `max` `pg` `ts` `vd` `multi` `f` がプロトタイプと仕様書の値どおり。
- [ ] `net`（`data` / `dl` / `own` / なし）と `perm`（`geo` `notify` `mic` `clipboard`）が正しい。接続の点・はじめてのダウンロードの帯・許可のお願いは共通の枠が登録から出す（実装ガイド 4章「通信と許可の出し方」）。ウィジェットの中で別の出し方を作らない。
- [ ] `priv`（人前では隠すの既定）: 仕様書 3章「人前では隠す」で既定オンのもの（メモ・TODO・予定・クリップボード・AIチャット・翻訳・受け渡し・表・スクリプト・タイムログ・スケッチ）は true。**`vd`（入力が主役で前面表示できるか）とは別の意味で、`vd` から導かない。**
- [ ] `states`（出しうる状態: 読み込み中・更新中・空・失敗・古い内容・許可待ち）、`refresh`（更新の間隔と、表示中だけ更新するか）、`run`（実行の寿命。下の「実行の寿命」）、`keys`（ウィジェットの中だけで使うキー。操作ヒントとキーの衝突を確かめる）を埋める。
- [ ] `store` は `WIDGET_DATA` の定義から引く（同じ定義を二重に書かない）。
- [ ] `icon` と `share` は値が決まるまで未定義でよい。**`share`（記録の共有）は未決定（実装ガイド 7.6）なので勝手に決めない。既定は独立。**
- 登録への `priv` `states` `refresh` `keys` `store` の追加と、共通の枠が登録から出す仕組みはこの PR で対応中（review #6）。

### 種類 ID と配置 ID（review #5、この PR で対応中）
- [ ] 部品は**配置 ID を受け取り、`useWidget()` で自分の区画（`cfg`・`data`）だけを読む**。ほかの区画を読まない。
- [ ] 種類 ID を文字列で直書きしない（`d.cfg['links']`、`id === 'clock'` のような分岐を書かない）。最初の1個は配置 ID＝種類 ID だが、2個目は `<kind>#<n>`（`links#2`）になる。
- [ ] `multi: false` の種類は2個目を作れない前提で書く。`multi: true` でも、複数置く UI は P3。
- [ ] 全画面（`pg: true`）は `pgW[配置ID]` で決まる大きさの1つ。全画面・置かずに使う・前面表示でも同じ配置 ID の設定と記録を使う。土台（レイアウト・シェル）に種類ごとの分岐を足さない。

### 記録の版と保存しないもの（review #1・#7）
- [ ] 記録に `version` を持つ。形を変えたら `version` を上げ、古い版を移す `migrate` と古い版の fixture を足す（区画には `v` と `dv`＝この `version` が書かれる。この PR で対応中）。
- [ ] `sanitize` は知らない項目を捨て、足りない項目は既定値で補い、不正な値（型・値域・長さ・重複・参照切れ）を既定値にする。同じ検証を UI・復元・import で使う。
- [ ] **保存しないもの**（実装ガイド 6章）を `cfg`/`data` に入れない: 画面の一時状態（開いているシート・今の画面・前面表示・再生中かどうか）、録音、画像変換の一覧と画像、現在地、スクリプトの実行結果、「会話を保存」がオフのときの会話、生成途中の応答。鍵・認証情報は保存も書き出しもしない。保存しないことをテストで確かめる。
- [ ] **大きな記録**（受け渡し・AIチャット・表・スクリプト・録音・画像変換など、画像・会話・表・コード）は localStorage に入れず、**非同期の記録の保存先**（IndexedDB）を使う（最小限の境界はこの PR で対応中。全面対応は P3）。

### プライバシー（仕様書 3章「人前では隠す」、review #6）
- [ ] 隠している間は**中身を描かず、読み上げにも出さず、中身のある知らせ（状態の覆い・1×1 のトースト・通知）も出さない**。通常・前面表示・全画面・状態の覆いのどれでも同じ。
- [ ] **隠すことを止める理由にしない**。判定と実行は続け、通知は共通の `notify()` が伏せた文で出す（種類の側で `d.veiled(id)` を見て通知を止めたり文を変えたりしない）。
- [ ] Storybook に「人前では隠す」の状態がある。1×1＋失敗・空＋隠す、通常→全画面＋隠すを確かめる。

### 状態と更新（仕様書 3章「状態」「段階表示」、review #7）
- [ ] 外部の情報を使うなら5状態（通常・読み込み中・更新中・空・失敗）。利用者が書きためるものなら空の状態。
- [ ] **表示中の画面だけ更新する**。未配置・表示中でない画面では基本の段も更新しない。出ていない段は要素を作らず、データも取りに行かない。表示されたときに古ければ「更新中」を経て差し替える。
- [ ] 古い非同期応答を捨てる。unmount で timer・購読を止める。重いものは表示されるまで描画しない。

### 実行の寿命（run と Runner。開発フロー 4章「実行の寿命」、schema v0 R14）
- [ ] 登録の `run` を開発フロー 4章の表で選ぶ: 受動・表示更新は `none`（表示更新は `refresh` で表す）、明示して始めて止める・完了するものは `continuous`、設定でオンにして期限やイベントを待つものは `watch`、明示した Run で動くものは `request`。**表示の更新を `run` に重ねて書かない**。値が違う・足りないときは UI/UX 実装層に頼む（登録はその持ち物）。
- [ ] **外す・置き場所の変更・画面の移動・前面表示や全画面・unmount・一時利用を閉じる、で実行を止めない**。止めるのは利用者の操作（止める・一時停止・リセット・オフ）と完了だけ。表示中だけの描き直しは止めてよい。
- [ ] 見えていなくても・未配置でも**決まった時刻に何かをする**（鳴らす・完了・知らせる）なら `runner.ts` の `Runner` を書いて `WIDGET_RUNNERS` に登録する。始めた時刻から計算できるだけ（ストップウォッチ・打刻）なら書かない。
- [ ] 期限は `ctx.at()`／`ctx.cancel()` で持つ（自分で `setTimeout`・`setInterval` を張らない）。callback は作ったときの実行 ID を持ち、今の実行 ID と違えば何もしない。完了したら状態を変えて二重の完了を防ぐ。設定・記録の変化は `watch(…, { immediate: true, flush: 'sync' })` で見て予定を立て直す。
- [ ] 遅れた timer はそのときの時刻で判定する。**古すぎる期限の扱いを決めて書き、テストする**（例 アラームは1分より前に過ぎた分を鳴らさない、過去の分をまとめて鳴らさない）。音・通知の前に `ctx.owns('<task>')` を見る（P3 の Web Locks の取り決め。今は常に担当）。
- [ ] 始めるのは明示の操作だけ。mount・開き直し・一時利用を開くことで始めない・二重に始めない。
- [ ] 実行状態は `runtimeOf(d)`（`status.ts` から）に置き、`cfg`/`data` に入れない。再読み込みで消えてよい（実装ガイド 6章）。保存するのは利用者の設定と記録だけ。
- [ ] 描き直しは `useShownNow` / `useFaceClock`（`src/widgets/shared/time.ts`）を使い、見えない間・タブが裏の間は timer を持たない。残り・経過は終わる時刻・始めた時刻から計算する（1秒ごとに数えない）。
- [ ] 代表の場面（未配置、一時利用を閉じる・開き直す、置き場所の変更、画面の移動、人前では隠す、止める・リセット、期限の到来、タブが裏から戻る、再読み込み）を、部品を描かない fixture（`src/app/runtime/test-fixtures.ts`、fake timers）でテストする。
- `request`（要求実行）は取り決め（`RequestPhase`、上限は期限、古い結果は実行 ID で捨てる）だけがある。実処理は P2d・P4（#16）。録音・ミュージック・環境音の持ち方は未決定（`docs/lgd/p2a-followup.md`「残したこと」）。

### 通知（共通の仕組みを使う・専用の通知を作らない。開発フロー 4章「通知」、schema v0 R15）
- [ ] 通知を出す種類は登録の `perm` に `notify` を持ち、`states` に `perm` を持つ。通知の設定は `f` の `tg` の項目 `notify`（例「完了を通知」）。項目が無ければ常にオン。
- [ ] 送るのは `ctx.notify(msg)`（`Runner` の中）か `notify(d, id, msg)` だけ。`key` は1回の出来事で一意（配置 ID と実行 ID・鳴る時刻を入れる）。**`Notification` を直接使わない。独自のトースト・重複の判定・伏せた文を作らない。** 送れなかったときも実行は止めない。
- [ ] 許可のお願いは明示の操作から `askNotify(d, id, 文, then?)` で始め、文は `<kind>.ts` に置く。カードは共通の枠が `notifyCover()` で出すので、種類の中に許可のカードを作らない。断られても実行は続く（「このまま始める」）。
- [ ] 設定パネルの「ダッシュボードを開いている間だけ知らせます」は共通の部品（`NotifyOpenNote.vue`）が `perm: notify` の種類に自動で出す。種類ごとに書かない。
- [ ] 伏せた文（「通知があります…」）にウィジェット名・時刻・内容が出ないこと、同じ key が1度だけ出ることをテストする。

### 元に戻す（仕様書 7章、review #3）
- [ ] 共通の履歴の対象は仕様書 7章の範囲（ボード・置き場所・並び順・大きさ・未配置・全体設定・ウィジェット設定・ハビットとクイックリンクの項目）だけ。TODO・メモなどの記録は**そのウィジェットの操作の中で個別の「元に戻す」**を持つ。
- [ ] 追加・削除を戻すときは**その操作で足した・消した行の ID だけ**を戻し、ほかの編集は残す。上限で古い行が落ちた場合は、その行も戻す。テストで「追加→別の編集→元に戻す」で別の編集が残ることを確かめる。

### 見本・模擬と実際の機能（review #9、実装ガイド 付録）
- [ ] P4 まで見本・模擬で動くものを実際の機能と区別する。`net: 'data'` は接続の点（未接続の輪）で見本と示す。`dl`・`own` の模擬（ローカルAI・受け渡し）は実際のダウンロード・送信の成功として見せない。
- [ ] プロトタイプ専用の機能（全体設定の「表示テスト」「すべて並べる」、画像変換の「見本で試す」、傘の「サンプル」）を本番の機能として足さない。
- [ ] **未実装を成功扱いにしない**。まだ作っていない操作・失敗した書き出しを「できました」と知らせない。中身の無い種類は「準備中」の置き換えになる（この PR で対応中）。
